# 聊天界面测试说明

> 状态：已从“理想化测试方案”收敛为“当前实现导向的测试说明”。

旧版本测试文档大量引用了并不存在的统一 `ChatInterface` 组件结构和未来态测试用例。当前仓库里最明确的聊天实现是 `SimpleChatInterface.tsx`，因此这份文档改为围绕现状说明。

## 当前应优先测试的对象

### 组件级

- `frontend/src/components/SimpleChatInterface.tsx`
- `frontend/src/components/DocumentUpload/`

### 页面/功能级

- 聊天请求发起
- 响应展示
- Markdown 渲染
- 超时与错误提示

## 当前更合理的测试层次

### 1. 组件冒烟测试

目标：

- 组件能渲染
- 初始欢迎消息能显示
- 输入框和发送按钮可交互

### 2. 行为测试

目标：

- 用户输入后能追加用户消息
- 请求期间会出现 loading 状态
- 成功响应后助手消息内容会更新
- 失败时能显示错误提示

### 3. 集成测试

目标：

- 与当前后端测试接口的交互可验证
- 文档上传与聊天相关页面不会互相破坏基础状态

## 当前不再继续保留的失效测试前提

本次移除了这些不再可靠的前提：

1. 默认存在统一 `ChatInterface` 组件树
2. 默认存在完整 WebSocket 聊天协议测试闭环
3. 默认存在旧版组件目录结构
4. 大量未来式 E2E 场景直接当作当前测试基线

## 当前建议的最小测试清单

1. `SimpleChatInterface` 能渲染
2. 输入文本后可发送
3. 成功响应可显示助手回复
4. 超时或网络失败时可显示错误文案
5. Markdown 内容能正确渲染

## 后续建议

如果后面要恢复更完整的测试文档，建议先做两件事：

1. 先确定聊天主组件是否仍然是 `SimpleChatInterface`
2. 再根据真实组件结构补单元测试与集成测试说明
